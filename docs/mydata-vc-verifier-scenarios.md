# MyData 文件 → 選擇性揭露憑證：測試場景與信任邊界

日期：2026-09-01

## 先定義產品承諾

MyData 下載的 PDF／CSV 是使用者保存在手機上的來源文件，**不會因為 App 把欄位包成 VC，就自動變成政府簽發的 VC**。第一階段應叫「由持有人從 MyData 文件衍生的主張」，驗證頁必須同時顯示：

- 持有人簽章是否有效；
- 來源文件 SHA-256 是否與保險箱紀錄一致；
- 使用的解析器版本與欄位／條件規則；
- 文件本身是否有可驗證的機關簽章；
- 信任標籤是「政府簽發」或「持有人從文件衍生」，不可混用。

若來源 PDF 沒有可驗證的機關簽章，驗證端只能證明「同一位持有人簽了這項主張，且它連到這份文件指紋」，不能證明政府認可該主張。

## verifier.mashbean.net 的三個最小測試場景

### 1. 租屋／補助的所得門檻

輸入：個人所得資料或納稅證明。

只揭露：年度、是否落在查驗方要求的區間、來源文件指紋。不要揭露精確所得、扣繳單位、每筆明細、身分證字號。

驗證頁問題應寫成：「這位持有人在 2025 年的所得是否介於申請門檻內？」結果要同時呈現 predicate、年度與信任標籤。

### 2. 到職／福利申請的投保狀態

輸入：勞保或健保投保資料。

只揭露：指定日期是否有效投保、資料涵蓋期間、來源文件指紋。不要揭露歷任雇主、投保薪資、與查驗目的無關的期間。

驗證頁問題應寫成：「在 2026-09-01 是否有有效投保？」不要把「曾經投保」與「當天有效」混成同一個答案。

### 3. 地方資格／居住或所有權條件

輸入：戶籍或地籍資料。

只揭露：縣市／行政區 predicate、設籍期間 predicate，或是否符合指定所有權條件。不要揭露完整地址、戶內人口、地段地號、持分與他項權利。

驗證頁問題應寫成具體條件，例如：「是否在臺北市設籍滿六個月？」而不是模糊的「地址已驗證」。

## 最小資料格式

每個文件類型各自有版本化 schema，不做「任意 PDF 都自動變 VC」。建議衍生 payload 至少包含：

```json
{
  "vct": "https://verifier.mashbean.net/vct/mydata-derived-income/v1",
  "source": {
    "kind": "mydata-downloaded-document",
    "sha256": "...",
    "document_type": "income",
    "parser": "income-pdf/v1"
  },
  "claims": {
    "tax_year": "2025",
    "income_in_requested_range": true
  },
  "assurance": "holder-derived"
}
```

可揭露 claims 應以 SD-JWT disclosure 承載；predicate 的規則、邊界值、幣別與年度必須進入簽章涵蓋範圍，不能只寫在 verifier 的 UI。

## 上線閘門

1. 真實文件逐類驗證 PDF／CSV 格式與版本差異。
2. parser 有去識別化 fixture、錯誤格式拒絕、OCR／文字層差異與邊界值測試。
3. 讀取並驗證來源文件的機關簽章；沒有就顯示「未驗到機關簽章」。
4. App 產出的憑證可選擇性揭露，未勾欄位不進 presentation。
5. verifier.mashbean.net 驗簽、檢查 schema／規則版本，並顯示來源與 assurance。
6. 在兩支真機跑過掃碼、同意、揭露選擇、驗證結果與撤回／刪除流程。

在這六關之前，App 可以提供匯出與測試場景說明，但不應放出看似可用的「製作政府 VC」按鈕。
